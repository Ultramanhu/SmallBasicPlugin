## 第一部分：测试方案

### 1. 测试金字塔

```
                 ┌────────────────────────────┐
                 │  E2E / IDE 集成测试          │  少量、关键路径
                 │  (VS Code test-electron /    │
                 │   VS Experimental Instance)  │
                 ├──────────────────────────────┤
                 │  协议与组件测试              │
                 │  DAP 适配器 / VS MEF 组件    │
                 ├──────────────────────────────┤
                 │  语言核心单测                │  大量、快速
                 │  (vitest / xunit)            │
                 ├──────────────────────────────┤
                 │  双引擎一致性测试集            │  跨仓库共享
                 │  (.sb + 期望输出/调试脚本)     │
                 └──────────────────────────────┘
```

### 2. 语言核心单测（复用现有资产）

| 侧 | 框架 | 来源 | 覆盖 |
|---|---|---|---|
| TS | vitest（仓库根） | `vendor/SmallBasicOnline/tests/compiler`，经 `packages/smallbasic-lang-core/tests/legacy-compiler.spec.ts` 直接 import `tests-list` | scanner/parser/binder/runtime/services 全套 |
| TS 补充 | vitest | `packages/smallbasic-lang-core/tests/` | `runtime-compat`、`completion-service-regressions`、`documentation-localization` |
| .NET | xunit 2.9.2 + FluentAssertions 7.0.0 | `tests/SmallBasic.Compiler.Tests`（net8.0-windows） | Scanning/Parsing/Binding/Runtime/Services + Editor 组件（Snippet/Outline）+ RunHost 运行时/条件表达式 |

两侧现成的测试辅助语义等价（`verifyRuntimeResult(text, input, output)` ↔ `VerifyLoggingRuntime`），是移植正确性的第一验证。

### 3. 双引擎一致性测试集（尚未落地，下为目标形态）

原计划在 `visual_studio_code_plugin/conformance/` 下建立共享的 `.sb` 程序 + 期望 transcript 测试集，由 TS 与 .NET 两侧 runner 对跑。**当前仓库没有该目录**；一致性主要依赖两侧各自的既有测试套件（`tests/compiler` ↔ `SmallBasic.Compiler.Tests`）以及 `runtime-compat` 补充用例间接保障。

目标形态：

```
conformance/
├── programs/           # .sb 测试程序（覆盖全部语句/运算符/库调用/事件）
│   ├── statements/  expressions/  libraries/  events/
├── expected/           # 每程序一个期望 transcript（TextWindow I/O 日志 + 终态内存）
└── debug/              # 调试场景脚本 DSL（断点行集合 + 期望停止序列 + 变量快照）
```

执行器（两侧各一个薄 runner）：

- TS：`conformance.runner.ts` — 逐程序 `new Compilation` → `ExecutionEngine` + 假 I/O → 实际 transcript 与 expected 比对。
- .NET：`SB.Conformance.Tests` — 同一批 `.sb` 走 `SmallBasicEngine` + `LoggingTestLibraries` 模式 → 比对。

### 4. DAP 适配器协议测试

- **TS 适配器**：`packages/smallbasic-vscode/tests/debug-session.spec.ts` 用自建 DAP 客户端驱动内嵌适配器，端到端覆盖：运行、Web 内存源、断点/步进/变量/求值、条件断点（真/假/非法）、空行吸附、输入桥接、`stopOnEntry`、配置先于 launch、图形程序拒绝。
- **.NET 适配器**：暂无独立 DAP 协议测试；`tests/SmallBasic.Compiler.Tests` 的 `Runtime`/`Editor` 用例覆盖 RunHost 运行时与条件表达式。
- **目标形态**：跨后端的统一调试 DSL（`conformance/debug/*.dbg`）对跑，比对停止序列与变量快照——尚未落地。

### 5. IDE 集成测试

| 侧 | 手段 | 关键用例 |
|---|---|---|
| VS Code | vitest 组件测试（`packages/smallbasic-vscode/tests/`） | 清单校验（manifest）、默认后端选择、DAP 会话、文档符号、补全范围、上下文补全 |
| VS | xunit（`SmallBasic.Compiler.Tests`）+ Experimental Instance 人工冒烟 | 分类 span、补全项、ErrorTagger、Snippet、大纲、RunHost 运行时 |

**着色一致性**：原计划的跨 IDE “token→分类” 快照比对尚未落地。

### 6. 测试门禁（目标，当前无 CI）

仓库暂无 CI 配置；本地验证命令：

```
1. cd visual_studio_code_plugin && npm install && npm run typecheck && npm test
2. dotnet test visual_studio_plugin/SmallBasic.VisualStudio.slnx   # SmallBasic.Compiler.Tests
3. .\Build-All.ps1                                                  # 打包冒烟（vsix / VSIX）
```

目标形态：PR 触发 lint+typecheck、两侧核心测试、DAP 协议测试、VS Code 集成测试与打包冒烟；主分支追加 VS Experimental Instance 冒烟。

## 第二部分：性能方案

### 1. 性能预算

| 指标 | 预算 | 依据 |
|---|---|---|
| 全量编译（1k 行典型教学程序） | < 5 ms | 在线版每次击键全量编译已验证可行 |
| 全量编译（10k 行极端） | < 50 ms | 超出则防抖内一次，用户无感 |
| 补全响应（缓存命中） | < 30 ms | VS/VS Code 补全体感阈值 ~100ms |
| 诊断刷新延迟 | ≤ 300 ms（防抖 150 + 编译 + 渲染） | |
| 着色重分类（VS）/语义令牌（VS Code） | < 16 ms/帧级 | 不阻塞键入 |
| 调试逐行推进开销 | < 1 ms/行（判定） | 适配器循环 O(1) |
| 扩展激活 | < 200 ms（懒激活 onLanguage） | |
| 包体积 | VS Code vsix 当前约 18 MB（含 windows/portable/blazor 三份宿主）；VSIX 当前约 17 MB | 实际值 |

> 上表除包体积外均为**设计目标值**，尚未建立基准测量。

### 2. 性能手段清单

**语言核心**：
- 编译缓存以 `(uri, version)` / `(ITextBuffer, ITextVersion)` 为键，四个语言功能共享一份 `Compilation`。
- 诊断防抖 150ms；补全/悬停走同步缓存路径。
- 引擎为同步全量编译——不引入增量解析复杂度（SB 程序规模不需要）。

**VS Code 侧**：
- 懒激活（`onLanguage:smallbasic`）；esbuild 单文件打包消除模块加载开销。
- 运行/调试在独立 Node 子进程，扩展宿主永不阻塞。
- 调试循环 `setImmediate` 分段（每段 ≤5ms），保证 pause 请求即时响应。
- >5 万行极端文件：二期迁 web worker（接口已按纯数据设计，迁移零 API 变化）。

**VS 侧**：
- 解析/绑定在后台线程，结果经 `Task` 投递 UI 线程；`IAsyncCompletionSource` 全程异步。
- 分类器按可见区域增量请求（VS 自行分片调 `GetClassificationSpans`），实现上仍全量扫描但仅返回请求区间 span。
- `SBCompilationService` 在缓冲关闭时主动释放。

**测量保障（尚未落地）**：`benchmarks/` 目录、BenchmarkDotNet 配置与集成埋点均未实现；上述预算尚未通过基准测量验证。
