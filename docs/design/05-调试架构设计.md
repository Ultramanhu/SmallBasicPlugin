# 05 调试架构设计

目标：两端 IDE 一致的调试体验——**断点、单步（逐语句/步入/步出）、暂停、继续、变量查看、调用栈、程序终止**。

> **2026-09-28 实施状态**
>
> - **VS Code**：三后端调试均已落地。JS 后端为内嵌调试器（`packages/smallbasic-vscode/src/debug/`，进程内驱动 TS `ExecutionEngine`，Web 端以 `DebugAdapterInlineImplementation` 内联运行）；C# 后端为 `SmallBasic.RunHost debug`（原生 DAP over stdio，驱动 .NET `SmallBasicEngine` 的 `NextLine` 模式，见 `visual_studio_plugin/src/SmallBasic.RunHost/Debug/`）；Blazor 后端为 `SmallBasic.Blazor.RunHost debug`（文本程序本地调试，图形程序经 WebSocket 桥接浏览器 WASM）。launch.json 以 `backend: javascript | csharp | blazor` 选择后端，以 `mode: cli | web` 选择命令行或浏览器模式；Web 模式支持 JavaScript/Blazor，VS Code for Web 强制使用 Web 模式。三者断点吸附/单步/变量/输入桥接语义对齐（断点吸附依赖 vendor 编译器新增的 `SmallBasicCompilation.GetExecutableLines()`）。Windows 桌面版未显式配置后端时默认 C# 图形宿主；Web、Linux 和 macOS 默认 JS。
> - **Visual Studio 2022/2026**：三后端均经 Debug Adapter Host 接入（`DebugAdapterHost.Launch` + 临时 launch.json）。F5/F10/F11 默认启动随 VSIX 分发的纯 C# DAP；Tools 菜单另有 C#/JS/Blazor 运行与调试的显式入口。JS 路径只分发 bundle，使用外部 Node.js 20+，并在启动前拒绝图形程序。命令过滤器在调试会话激活期间把 F5/F10/F11 全部转发给调试器。
> - **图形程序调试**：Windows C# 宿主支持 `GraphicsWindow`、`Shapes` 和 `Turtle`；Blazor 后端在浏览器内以 SVG/Canvas 支持同样的图形库；JS 与 portable C# 宿主仍为文本模式，并显式返回 capability 错误。`Controls` 等尚未实现的库仍会返回明确的“不支持”错误。
> - **适配器不是独立包**：调试适配器内嵌在各宿主/扩展中（TS 内嵌于扩展、C#/Blazor 内嵌于对应 RunHost），不存在独立的 `sb-debug` 或 `SB.DebugAdapter`。

## 1. 为什么是 DAP

| 选项 | 评估 |
|---|---|
| **DAP 调试适配器** | VS Code 原生支持；VS 2026 经内置 **Debug Adapter Host** 支持。一套协议两端通吃，UI 全部复用 IDE 标准调试界面 |
| VS AD7 自研调试引擎 | 接口数十个、注册表/COM 集成复杂，工作量约为 DAP 方案的 10 倍，否决 |
| 自绘调试 UI | 两端的旧版在线编辑器即此模式（Monaco 行高亮 + 自绘变量面板），现代 IDE 插件无必要，否决 |

协议统一、引擎双实现：

```
VS Code   ──DAP──> 内嵌 TS DAP (dist/debug/adapter.js)      ──> ExecutionEngine (TS)    ← 默认(非 Windows)/Web
          ──DAP──> SmallBasic.RunHost debug (.NET)          ──> SmallBasicEngine (.NET) ← Windows C# 图形
          ──DAP──> SmallBasic.Blazor.RunHost debug (.NET)   ──> WASM engine (Blazor)    ← 跨平台图形
VS 2022/26 ─DAP──> SmallBasic.RunHost.exe debug (.NET)      ──> SmallBasicEngine (.NET) ← F5 默认
          ──DAP──> SmallBasic.Blazor.RunHost debug (.NET)   ──> WASM engine (Blazor)
          ──DAP──> node debugadapter/adapter.js (TS)        ──> ExecutionEngine (TS)
```

两端 IDE 通过 launch.json 的 `backend` 与 `mode`（VS Code）或 Tools 菜单（VS）选择调试/运行后端及承载模式（ADR-5），三个适配器 DAP 语义字段级对齐（见 §5），IDE 调试 UI 完全一致；语言智能不受选择影响，始终用 IDE 原生引擎。

## 2. 引擎调试能力现状与断点补齐

两个引擎均**无断点**，但都有**行级暂停钩子**：

| 引擎 | 暂停机制 | 状态快照 |
|---|---|---|
| TS `ExecutionEngine` | `execute(ExecutionMode.NextStatement)`：指令 `sourceRange.start.line` 变化即置 `Paused` 返回 | `executionStack`（帧栈）+ 指令 `sourceRange`、`memory`（全局变量） |
| .NET `SmallBasicEngine` | `Mode=NextLine`：行变化即 `Pause()`（`SmallBasicEngine.cs:112-119`）；`Mode=Debug` 不自动停 | `GetSnapshot()` → `{ CurrentSourceLine, ExecutionStack, Memory }` |

**断点实现（适配器层，零引擎修改）**：适配器运行循环统一为"逐段推进 + 命中判定"：

```
loop:
    engine.execute(NextLine/NextStatement)     // 推进到下一个源码行边界
    line := 当前行（栈顶帧指令 sourceRange 或 engine.CurrentSourceLine）
    if stepping 或 line ∈ breakpoints[file]:   // O(1) 集合查找
        上报 DAP stopped (reason: breakpoint | step)
        等待 DAP continue/next/stepIn/stepOut 请求
    else if engine.State == Terminated:
        上报 terminated；退出
```

- 每次循环只执行到行边界即返回，断点判定开销 O(1)；SB 程序规模下逐行推进的额外开销可忽略（解释器本身为纳秒~微秒级/指令）。
- **步入/步出**：SB 仅有子程序调用（无嵌套定义）。`stepIn`=NextLine 即自然步入；`stepOut`=记录当前栈深，循环推进直到栈深 < 记录值后暂停；`next`=栈深 ≤ 当前值时在行边界暂停。
- **断点校验**（`setBreakpoints` 响应）：把断点行映射到最近的可执行语句行——用 `Compilation` 的 AST/指令 `sourceRange` 集合做"行 → 最近 ≥ 该行的可执行行"吸附，并返回 `verified: true/false`（空行/注释行 verified=false）。
- **输入阻塞**：`BlockedOnInput/BlockedOnStringInput` 期间适配器不视为 stopped；输入到达后 `InputReceived()` 继续循环。
- **暂停请求**（`pause`）：TS 引擎同步循环需让出事件循环——适配器以 `setImmediate` 分段驱动（每段推进至多 N 行或 5ms），段间检查 pending 的 pause 请求；.NET 引擎直接 `engine.Pause()`。

**可选上游补丁（二期优化）**：在两个引擎各加一个 `ShouldPause(line): boolean` 委托，由引擎内部在行边界回调，免除适配器外层循环。非必需，MVP 不做。

## 3. TS 调试适配器（内嵌于扩展）

技术栈：`@vscode/debugadapter`（`LoggingDebugSession` 基类）+ `@vscode/debugprotocol`。源码位于 `packages/smallbasic-vscode/src/debug/`：`session.ts`（核心）、`factory.ts`（适配器工厂）、`adapter.ts`（Node 入口）、`node-source-accessor.ts`、`inline-values.ts`；Web 走 `src/web/debug-factory.ts` + `src/web/source-accessor.ts`。

```ts
class SmallBasicDebugSession extends LoggingDebugSession {
  // 声明能力：supportsConfigurationDoneRequest / supportsConditionalBreakpoints
  protected initializeRequest(...)
  protected setBreakPointsRequest(...)     // 校验+吸附（getExecutableLines），支持条件断点
  protected configurationDoneRequest(...)
  protected launchRequest(...)             // new Compilation → new ExecutionEngine
  protected threadsRequest(...)            // 单线程，thread id=1
  protected stackTraceRequest(...)         // executionStack 帧 + 指令 sourceRange → StackFrame
  protected scopesRequest/variablesRequest // Globals 作用域，数组递归展开
  protected continueRequest/nextRequest/stepInRequest/stepOutRequest
  protected pauseRequest/disconnectRequest
  protected evaluateRequest(...)           // 变量名求值；TextWindow 等输入时作为输入并 resume
}
```

**执行循环**：时间片驱动（每段约 5ms / 128 步），段间响应 DAP 请求；`stopOnEntry` 直接发 `StoppedEvent("entry")`。

**变量呈现**：`engine.memory`（`ArrayValue`，键值字典）→ DAP `Variable[]`；SB 数组递归展开，`variablesReference` 惰性加载。标量显示 `value.ToString()` 与类型（Number/String/Array）。

**I/O 通道**：`debug` 模式下 TextWindow 的读写经 DAP `evaluate` 请求承载——程序 `Read/ReadNumber` 阻塞时适配器提示输入，用户输入作为表达式求值回注并 resume。

launch.json 属性：`program`（必填，默认 `${file}`）、`backend`（`javascript|csharp|blazor`，无默认值）、`mode`（`cli|web`，默认 `cli`；Web 模式支持 `javascript|blazor`）、`stopOnEntry`（默认 `true`）。VS Code for Web 会把 `mode` 强制为 `web`。

## 4. .NET 调试适配器（内嵌于 RunHost）

有两个 .NET 适配器，均用 `System.Text.Json` 手写 DAP 帧（`Content-Length` 头 + JSON），消息模型与 TS 版字段级对齐（同一 launch.json schema）：

- **`SmallBasic.RunHost`**（`Debug/DebugAdapter.cs` + `Debug/DapStream.cs`）：`debug` 子命令进入 stdin/stdout DAP 模式；支持 `initialize/launch/setBreakpoints/configurationDone/threads/stackTrace/scopes/variables/continue/next/stepIn/stepOut/pause/evaluate/disconnect`；Globals 作用域（`variablesReference=1`）、数组可展开、条件断点用 `Compilation.CompileExpression` + `engine.EvaluateConditionAsync`、断点吸附用 `GetExecutableLines()`；`#if !GRAPHICS_HOST` 时拒绝图形程序。
- **`SmallBasic.Blazor.RunHost`**（`Debug/BlazorDebugAdapter.cs`）：文本程序直接用宿主内解释器调试；图形程序把 DAP 桥接到浏览器 WASM 会话（见 [09](./09-Blazor后端与RunHost.md)）。

**I/O 桥接**：`debug` 模式下进程 stdin/stdout 被 DAP 独占，因此 `TextWindow` 的输入输出经 DAP 事件/`evaluate` 请求承载（与 TS 适配器一致），而非直接读写控制台。

**VS 接入**：VSIX 的 `SmallBasicDebugLauncher` 通过 DTE 执行 `DebugAdapterHost.Launch /LaunchJson:"<path>"`，把适配器可执行文件与 `smallbasic` 类型写入临时 launch.json（**不使用 `vsdconfig`**，也不写 AD7 调试引擎）。

**已验证的请求子集**：`setBreakpoints/launch/stackTrace/variables/continue/next/stepIn/stepOut/pause/terminate/evaluate` 在 Debug Adapter Host 下均可用。

## 5. 两端调试语义对齐

| 语义 | 定义（两端一致） |
|---|---|
| 断点吸附 | 断点落在非可执行行 → 最近下一可执行行；`verified` 如实返回 |
| stepIn | 行边界暂停（自然进入子程序） |
| next | 栈深 ≤ 进入时栈深 的行边界暂停 |
| stepOut | 栈深 < 进入时栈深 时暂停 |
| 变量 | 全局变量字典全量展开；数组递归；暂停时刷新 |
| 调用栈 | 子程序帧，帧名=Sub 名，行号=指令 sourceRange |
| 异常 | 引擎 `exception`/诊断 → DAP `stopped(reason: "exception")` + 消息 |
| 终止 | 程序结束/用户停止 → `terminated` + `exited` |

对齐保障：`packages/smallbasic-vscode/tests/debug-session.spec.ts` 用自建 DAP 客户端对 TS 适配器做端到端校验（断点吸附/条件断点/单步/变量/输入桥接/图形程序拒绝等）。跨后端的统一调试 DSL 与对跑（原计划的 `conformance/debug/`）尚未落地（见 [07](./07-测试与性能方案.md)）。

## 6. 性能与安全

- 逐行推进循环仅在调试会话内启用；非调试运行走 `RunToEnd`，无开销。
- 分段驱动（TS 5ms/段）保证扩展宿主 UI 不冻结。
- 适配器不执行任何引擎外的代码；`File/Network` 等库在调试宿主中默认按 06 文档安全策略启用。
