# 01 源码现状分析

对 `official_repo` 三个 git 子模块的可复用资产调查结论。所有结论均来自对源码的直接阅读，关键路径见文中。

> **2026-09-28 现状校准**：本文记录的是**接入前**对上游源码的调查结论，作为选型依据仍然有效。落地时上游代码已被拷贝并升级到本地 `vendor/` 目录（[02](./02-技术选型与总体架构.md) ADR-4）：
> - TS 侧：`official_repo/online/src/compiler`、`src/strings`、`tests/compiler` → `visual_studio_code_plugin/vendor/SmallBasicOnline`（见其 `UPSTREAM.md`），再由 npm 包 `smallbasic-lang-core` 再导出。
> - .NET 侧：`official_repo/editor/Source` 的 `SmallBasic.Compiler`/`SmallBasic.Utilities`/`SmallBasic.Tests`/`SmallBasic.Editor/Libraries` → `visual_studio_plugin/vendor/SmallBasicEditor/Source`（见其 `UPSTREAM.md`）。
> - `visual_studio_plugin/` 与 `visual_studio_code_plugin/` 已不再是预留空目录，而是两个插件的实际实现位置。

## 2. SmallBasicEditor（.NET 侧资产）

路径：`official_repo/editor/Source/`

### 2.1 编译器 `SmallBasic.Compiler`（核心资产）

- **TFM netstandard2.0，零外部依赖**（仅依赖 `SmallBasic.Utilities` 资源库）。可直接被现代 .NET 与 VS 扩展（.NET Framework 4.8 / .NET 8）引用。
- 自研四段式编译管线（**非 Roslyn**）：
  - `Scanning/` — `Scanner` 词法分析，构造即完成全部扫描；`TokenKind.Generated.cs` 由 XML 生成
  - `Parsing/` — `Parser` 语法分析，AST 支持 `FindNodeAt(position)`
  - `Binding/` — `Binder` 语义绑定；`RuntimeAnalysis`（静态分析：是否用 TextWindow / 是否监听事件）
  - `Diagnostics/` — `Diagnostic`（`DiagnosticCode` + `TextRange`，**行列均 0 起始**）
  - `Runtime/` — 发射自研 IL 指令 + 栈式解释器
  - `Services/` — 语言服务（补全/Hover，直接产出 Monaco 形状 DTO）

### 2.2 关键公开 API

```csharp
// SmallBasicCompilation.cs —— 编译入口
public sealed class SmallBasicCompilation
{
    public SmallBasicCompilation(string text);              // 构造即完成 Scan+Parse+Bind
    public IReadOnlyList<Diagnostic> Diagnostics { get; }
    public RuntimeAnalysis Analysis { get; }
    public MonacoCompletionItem[] ProvideCompletionItems(TextPosition position);
    public string[] ProvideHover(TextPosition position);
}

// SmallBasicEngine.cs —— 执行入口（含调试钩子）
public enum ExecutionMode { RunToEnd, Debug, NextLine }
public enum ExecutionState { Running, Paused, BlockedOnStringInput, BlockedOnNumberInput, Terminated }

public sealed class SmallBasicEngine
{
    public SmallBasicEngine(SmallBasicCompilation compilation, IEngineLibraries libraries);
    public ExecutionMode Mode { get; set; }
    public ExecutionState State { get; private set; }
    public int CurrentSourceLine { get; private set; }
    public DebuggerSnapshot GetSnapshot();   // { 当前行, 调用栈帧, 变量内存字典 }
    public Task Execute();
    public void Pause();  public void Continue();  public void Terminate();
    public void InputReceived();             // 解除 Read/ReadNumber 阻塞
}
```

### 2.3 执行模型与调试能力

- **编译产物是自研 IL 指令 + 栈式解释执行，不是 MSIL**：`Runtime/ModuleEmitter.cs` 把绑定树降级为 `BaseInstruction` 列表（PushValue/LoadVariable/ConditionalJump/MethodInvocation/Pause/Terminate 等），`SmallBasicEngine` 逐条解释。
- **调试**：`NextLine` 模式每执行到新源码行即暂停（`SmallBasicEngine.cs:112-119`）；`GetSnapshot()` 暴露当前行/调用栈/变量。**没有断点机制**——需插件层基于 `CurrentSourceLine` 命中断点集合后 `Pause()` 实现（见 05 文档）。
- **运行时库是接口注入**：`Runtime/Libraries/` 只有生成的接口与元数据（`IEngineLibraries` 聚合 20 个库接口：Array, Clock, Controls, Desktop, Dictionary, File, Flickr, GraphicsWindow, ImageList, Math, Mouse, Network, Program, Shapes, Sound, Stack, Text, TextWindow, Timer, Turtle）。具体实现由宿主提供（Blazor 版实现在 `SmallBasic.Editor/Libraries/`）。**VS 插件需自行实现这 20 个接口**（见 06 文档）。
- **库元数据现成**：`Libraries.Generated.cs` 含全部库成员的名称、参数、描述，可直接驱动补全/悬停/签名帮助。

### 2.4 其他项目

| 项目 | 实质 | 对本方案的意义 |
|---|---|---|
| `SmallBasic.Editor` | Blazor 0.7 WebAssembly 应用（非 WPF），Monaco 经 JS Interop 接入 | 参考其 Monaco 接线方式；不可直接复用 UI |
| `SmallBasic.Server` | ASP.NET Core 2.1 静态托管，**不是 Language Server** | 无 |
| `SmallBasic.Analyzers` | 该仓库自身 C# 代码风格分析器 | 无 |
| `SmallBasic.Generators` | 离线代码生成器（XML → C#/TS） | 如需扩展库/节点可沿用其生成管线 |
| `SmallBasic.Tests` | xunit + FluentAssertions，内联 baseline（`^^^^` 位置标记比对诊断、`VerifyLoggingRuntime` 比对执行日志） | 测试方案样板，直接沿用 |
| `SmallBasic.Bridge` | Electron 桌面桥（File/Network/Process） | VS 控制台宿主的 File/Network 实现参考 |

**技术债**：仓库锁定 SDK 2.1.816（`global.json`）。`Compiler`/`Utilities` 两个 netstandard2.0 项目可直接在现代 SDK 构建（摘除 StyleCop/FxCop 旧分析器）；Editor/Server 不可直接构建，但不需要。

## 3. SmallBasicOnline（TS 侧资产）

路径：`official_repo/online/src/`

### 3.1 编译器 `src/compiler`（核心资产）

与 .NET 版同构的四段式管线：

- `syntax/` — `scanner.ts`、`tokens.ts`（`TokenKind` 枚举）、`statements-parser.ts`、`syntax-nodes.ts`、`ranges.ts`（`CompilerPosition/CompilerRange`，**0-based**）
- `binding/` — `modules-binder.ts`、`statement-binder.ts`、`expression-binder.ts`
- `emitting/` — `module-emitter.ts`、`instructions.ts`（栈式 IL，`BaseInstruction.execute(engine, mode, frame)`）
- `runtime/` — 值系统 + 标准库实现
- `services/` — **与 Monaco 完全解耦的语言服务层**
- `utils/diagnostics.ts` — `ErrorCode` 枚举 + `Diagnostic { code, range, args }`

### 3.2 关键 API

```ts
// compilation.ts —— 编译入口（构造即完成 scan→parse→bind）
export class Compilation {
    public readonly diagnostics: Diagnostic[];
    public get isReadyToRun(): boolean;
    public constructor(public readonly text: string);
    public emit(): { [name: string]: ReadonlyArray<BaseInstruction> };
    public getSyntaxNode(position: CompilerPosition, kind: SyntaxKind): BaseSyntaxNode | undefined;
}

// execution-engine.ts —— 执行 + 调试钩子
export enum ExecutionMode  { RunToEnd, Debug, NextStatement }
export enum ExecutionState { Running, Paused, BlockedOnInput, Terminated }
export class ExecutionEngine {
    public get executionStack(): ReadonlyArray<StackFrame>;  // 调用栈
    public get memory(): ArrayValue;                          // 全局变量
    public get/set state(): ExecutionState;
    public readonly programTerminated: PubSubPayloadChannel<Diagnostic | undefined>;
    constructor(compilation: Compilation);
    public execute(mode: ExecutionMode): void;               // 同步解释循环
    public terminate(exception?: Diagnostic): void;
}
```

- **调试**：`NextStatement` 逐语句暂停；当前行取栈顶帧指令的 `sourceRange`。**同样没有断点机制**。
- **宿主 I/O 插件接口**（对插件设计极为关键）：如 `text-window.ts` 的 `ITextWindowLibraryPlugin { inputIsNeeded(); checkInputBuffer(); writeText(); get/setForegroundColor(); ... }`，测试中用 `TextWindowTestBuffer` 注入假 I/O。VS Code 插件用终端/Webview 实现这些接口即可（见 06 文档）。
- **库元数据**：`runtime/libraries-metadata.ts`（`LibrariesMetadata`，含每个成员签名与文档 key）。

### 3.3 语言服务层（直接可映射 LSP/VS Code API）

```ts
// services/completion-service.ts
export module CompletionService {
    export function provideCompletion(compilation: Compilation, position: CompilerPosition): Result[];
}
// services/hover-service.ts
export module HoverService {
    export function provideHover(compilation: Compilation, position: CompilerPosition): Result | undefined;
}
```

诊断直接读 `compilation.diagnostics`。坐标系 0-based，与 LSP 一致（Monaco 是 1-based，现有 `app/editor-utils.ts` 的 ±1 转换逻辑可参考）。

### 3.4 缺口

- **没有 Monarch/TextMate 语法着色**（在线版连 Monaco 的 tokenizer 都没注册，着色需全新实现）。
- 没有 LSP 实现。
- 没有断点。
- 依赖陈旧（TS 2.5.3 / webpack 3 / monaco 0.10.1 / React 16）：**只提取 `src/compiler` + `tests/compiler` 现代化，不碰 app/UI**。

### 3.5 测试

Jasmine + Node 运行；`tests/compiler/helpers.ts` 提供 `verifyCompilationErrors`（ASCII 标尺比对）与 `verifyRuntimeResult(text, input, output)`（注入 `TextWindowTestBuffer` 驱动完整执行）——与 .NET 侧测试语义等价，为双引擎一致性测试奠定基础（见 07 文档）。

## 4. SmallBasicHomeSite（文档数据源）

路径：`official_repo/homesite/src/assets/documentation/xml/`

**核心发现：`SmallBasicLibrary.xml` 是高质量机器可读 IntelliSense 数据源**——标准 .NET XML 文档注释格式，2692 行，含 22 个本地化版本（`zh-Hans`、`ja`、`de`…）。

- `T:Microsoft.SmallBasic.Library.<对象>` → 库对象描述（20 个公开库对象）
- `M:...<对象>.<方法>(...)` → 方法：`<summary>` + 逐参数 `<param>` + `<returns>`
- `P:` / `E:` → 属性 / 事件
- `M:...Library.Keywords.<关键字>` → 语言关键字文档 + 示例代码

现成参考实现：`src/app/documentation/documentation.service.ts`（解析 XML、生成 `GraphicsWindow.DrawLine(x1, y1, x2, y2)` 形状签名的逻辑）。

**用途**：构建期把该 XML 转成两份资产——(1) VS Code 扩展用的 JSON（补全 detail/documentation、hover markdown、signature help）；(2) 验证两套编译器内置库元数据完整性的对账基准。

## 5. 资产复用结论

| 能力 | .NET 侧 | TS 侧 | 需新建 | 落地状态 |
|---|---|---|---|---|
| 词法/语法/语义/诊断 | ✅ `SmallBasicCompilation` | ✅ `Compilation` | — | ✅ |
| 补全/Hover | ✅ | ✅ | 坐标与协议适配层 | ✅ |
| 语法着色 | 有 Scanner tokens | 有 Scanner tokens | **TextMate 语法 + VS IClassifier** | ✅ 已实现 |
| 执行引擎 | ✅ `SmallBasicEngine`（异步、可暂停） | ✅ `ExecutionEngine`（同步循环） | 宿主 I/O 实现 | ✅ |
| 断点 | ❌ | ❌ | **适配器层断点命中逻辑** | ✅ 已实现（`GetExecutableLines` + 吸附） |
| DAP | ❌ | ❌ | **DAP 适配器** | ✅ 已实现（TS/C#/Blazor 三个内嵌适配器） |
| 库元数据/文档 | ✅ 生成代码 | ✅ 元数据类 | XML→JSON 构建脚本 | 🟡 直接用 vendor 本地化资源；构建脚本未落地 |
| TextWindow 宿主 | Blazor 版（不可用） | 插件接口（可注入） | **终端/控制台实现** | ✅ 已实现 |
| GraphicsWindow 宿主 | Blazor 版（不可用） | Konva 版（可参考） | **图形宿主** | ✅ 已实现（Windows C# 官方库 / 跨平台 Blazor SVG） |
