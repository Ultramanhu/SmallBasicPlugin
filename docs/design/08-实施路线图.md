> **2026-09-28 状态校准**：本路线图的最初里程碑划分已基本完成，但落地形态与原计划有出入——运行/调试从“双后端”变为**三后端（JS/C#/Blazor）**，图形在 Windows 用官方 C# 宿主、跨平台用 Blazor（而非原计划的 Webview/WPF 自绘），一致性测试集与性能基准未落地。下方表格已补充**当前状态**列。

## 1. M0 技术验证（Spike）

| Spike | 内容 | 通过条件 | 状态 |
|---|---|---|---|
| S1 | 拷贝 `official_repo/editor/Source` 的编译器/工具库到 `visual_studio_plugin/vendor/SmallBasicEditor`（netstandard2.0，SDK 风格项目，`.NET 8 SDK` 构建） | 全部既有测试通过；`UPSTREAM.md` 就位 | ✅ 完成 |
| S2 | 拷贝 `official_repo/online/src/compiler`+`src/strings`+`tests/compiler` 到 `visual_studio_code_plugin/vendor/SmallBasicOnline`（TS 5.x + vitest + Node 20） | 既有 jasmine 用例在 vitest 下全绿 | ✅ 完成 |
| S3 | VS Debug Adapter Host 挂载 DAP 适配器，验证关键请求 | 请求行为明确、限制记录在案 | ✅ 完成：改用 `DebugAdapterHost.Launch` + 临时 launch.json，无 `vsdconfig`；未使用 `runInTerminal`（I/O 经 DAP 事件/求值承载） |

## 2. M1 语言核心

- `visual_studio_code_plugin` monorepo 骨架；`vendor/SmallBasicOnline` 拷贝升级完成（TS 5.9 / vitest / `strict`；`UPSTREAM.md` 就位），`packages/smallbasic-lang-core` 作为再导出层。
- `visual_studio_plugin` 解决方案（`SmallBasic.VisualStudio.slnx`）；`vendor/SmallBasicEditor` 拷贝升级完成（SDK 风格、最新 LangVersion；`SmallBasic.Compiler.Tests` 通过）。
- **未落地**：`conformance/` 一致性测试集 v1、library-docs 生成脚本与元数据对账（见 [07](./07-测试与性能方案.md)）。

## 3. M2 编辑体验 MVP

**VS Code**：TextMate 语法、language-configuration、补全/悬停/诊断、语义令牌、文档大纲、`smallbasic.newFile` 与三个运行命令（JS/C#/Blazor）、打包流水线。

**VS**：内容类型与 `.sb` 关联、IClassifier、AsyncCompletion、QuickInfo、ErrorTagger、大纲/导航栏/折叠、三后端运行。

**未落地**：签名帮助；VS 侧项模板与“新建文件”命令；一致性测试集与着色快照测试；性能基准报告。

**M2 验收（双端）**：
1. 打开 `hello.sb` → 输入 `TextWindow.WriteLine("Hello")` 有补全与悬停文档；
2. 故意写错（缺 `EndIf`）→ 波浪线 + 错误面板条目，行列正确；
3. 运行 → 终端输出 `Hello`；含 `Read` 的程序可交互输入；
4. 打包产出 vsix / VSIX。

## 4. M3 调试

- JS 适配器内嵌于 VS Code 扩展（Node 入口 + Web 内联）；
- C# 适配器内嵌于 `SmallBasic.RunHost`，Blazor 适配器内嵌于 `SmallBasic.Blazor.RunHost`；
- VS 侧经 Debug Adapter Host（`DebugAdapterHost.Launch` + 临时 launch.json）接入；
- 断点吸附、stepIn/next/stepOut、变量/调用栈、异常停止、暂停、输入桥接。

**已验收**：`packages/smallbasic-vscode/tests/debug-session.spec.ts` 端到端覆盖主要场景；三后端在两端 F5 可用。
**未落地**：`conformance/debug/` 统一 DSL 双端对跑。

## 5. M4 图形库与发布

- **图形**：Windows 用 C# 宿主包裹官方 `Microsoft.SmallBasic.Library`（`GraphicsWindow/Shapes/Turtle`）；跨平台用 Blazor WASM + SVG/Canvas（见 [09](./09-Blazor后端与RunHost.md)）。
- **三后端**已就绪（ADR-5 的“双后端可选”扩展为三后端）；VS Code 内置 windows/portable/blazor 载荷，VS 侧 JS 复用外部 Node。
- **未落地**：VS Code Webview / VS WPF 自绘图形宿主（未采用，改由 C#/Blazor 承担）；File/Network 安全策略；Walkthrough 引导；CI 发布管线；Marketplace 正式上架（当前产物已生成 vsix/VSIX）。

**已验收**：`test/tutorial`、`test/tetris` 等图形样例可在 Windows C# 后端或跨平台 Blazor 后端运行。

## 6. 依赖与并行策略

```
M0(S1,S2 并行; S3 独立) ──> M1 ──> M2(两端并行) ──> M3(两端并行) ──> M4
```

- VS Code 线与 VS 线可并行推进；共享资产为 vendor 源码与示例程序。
- **未落地**：一致性测试集与 library-docs 生成器（原计划的共享资产）。
- 每个里程碑结束更新本文档与实际偏差记录（本次即为一次偏差校准）。
