## 1. M0 技术验证（Spike）

| Spike | 内容 | 通过条件 | 状态 |
|---|---|---|---|

| S2 | 拷贝 `official_repo/online/src/compiler`+`src/strings`+`tests/compiler` 到 `visual_studio_code_plugin/vendor/SmallBasicOnline`（TS 5.x + vitest + Node 20） | 既有 jasmine 用例在 vitest 下全绿 | ✅ 完成 |

## 2. M1 语言核心

- `visual_studio_code_plugin` monorepo 骨架；`vendor/SmallBasicOnline` 拷贝升级完成（TS 5.9 / vitest / `strict`；`UPSTREAM.md` 就位），`packages/smallbasic-lang-core` 作为再导出层。
- `visual_studio_plugin` 解决方案（`SmallBasic.VisualStudio.slnx`）；`vendor/SmallBasicEditor` 拷贝升级完成（SDK 风格、最新 LangVersion；`SmallBasic.Compiler.Tests` 通过）。
- **未落地**：`conformance/` 一致性测试集 v1、library-docs 生成脚本与元数据对账（见 [07](./07-测试与性能方案.md)）。

## 3. M2 编辑体验 MVP

**VS Code**：TextMate 语法、language-configuration、补全/悬停/诊断、语义令牌、文档大纲、`smallbasic.newFile` 与三个运行命令（JS/C#/Blazor）、打包流水线。

**VS**：内容类型与 `.sb` 关联、IClassifier、AsyncCompletion、QuickInfo、ErrorTagger、大纲/导航栏/折叠、三后端运行。

**未落地**：签名帮助；VS 侧项模板与“新建文件”命令；一致性测试集与着色快照测试；性能基准报告。

**M2 验收（双端）**：
1. 打开 `hello.sb` → 输入 `TextWindow.WriteLine("Hello")` 有补全与悬停文档；
2. 故意写错（缺 `EndIf`）→ 波浪线 + 错误面板条目，行列正确；
3. 运行 → 终端输出 `Hello`；含 `Read` 的程序可交互输入；
4. 打包产出 vsix / VSIX。

## 4. M3 调试

- JS 适配器内嵌于 VS Code 扩展（Node 入口 + Web 内联）；
- C# 适配器内嵌于 `SmallBasic.RunHost`，Blazor 适配器内嵌于 `SmallBasic.Blazor.RunHost`；
- VS 侧经 Debug Adapter Host（`DebugAdapterHost.Launch` + 临时 launch.json）接入；
- 断点吸附、stepIn/next/stepOut、变量/调用栈、异常停止、暂停、输入桥接。

**已验收**：`packages/smallbasic-vscode/tests/debug-session.spec.ts` 端到端覆盖主要场景；三后端在两端 F5 可用。
**未落地**：`conformance/debug/` 统一 DSL 双端对跑。

## 5. M4 图形库与发布

- **图形**：Windows 用 C# 宿主包裹官方 `Microsoft.SmallBasic.Library`（`GraphicsWindow/Shapes/Turtle`）；跨平台用 Blazor WASM + SVG/Canvas（见 [09](./09-Blazor与Web运行宿主.md)）。
- **三后端**已就绪（ADR-5 的“双后端可选”扩展为三后端）；VS Code 内置 windows/portable/blazor 载荷，VS 侧 JS 复用外部 Node。
- **未落地**：VS Code Webview / VS WPF 自绘图形宿主（未采用，改由 C#/Blazor 承担）；File/Network 安全策略；Walkthrough 引导；CI 发布管线；Marketplace 正式上架（当前产物已生成 vsix/VSIX）。

**已验收**：`sample/tutorial`、`sample/tetris` 等图形样例可在 Windows C# 后端或跨平台 Blazor 后端运行。

## 6. 依赖与并行策略

```
M0(S1,S2 并行; S3 独立) ──> M1 ──> M2(两端并行) ──> M3(两端并行) ──> M4
                                                      └──> M5(VS 侧, 依赖 M2/M3 的语言与调试能力)
```

- VS Code 线与 VS 线可并行推进；共享资产为 vendor 源码与示例程序。
- **未落地**：一致性测试集与 library-docs 生成器（原计划的共享资产）。
- 每个里程碑结束更新本文档与实际偏差记录（本次即为一次偏差校准）。

## 7. M5 Visual Studio 新框架迁移（已完成收敛为单包）

- **最终态**：`src/SmallBasic.Vsix`（新版扩展 SDK in-proc 混合托管 + 最小兼容 `AsyncPackage`）是唯一的 VS 包，产出 `SmallBasic.Vsix.<version>.vsix`；过渡期旧工程与公共库 `src/SmallBasic.VsCommon` 已删除，内容并入本工程，命名空间统一为 `SmallBasic.Vsix.*`。见 [04-VisualStudio插件设计.md](./04-VisualStudio插件设计.md)。
- **语言能力上 LSP**：`textDocument/completion` / `hover` / `documentSymbol` / `publishDiagnostics` 由进程内运行的 Small Basic language server 提供，语义仍来自 vendor 编译器；VS 的 LSP 客户端不会展开 snippet 占位符，因此补全文本在 `SmallBasicLspAnalysisService` 中摊平为普通参数名，旧 `SmallBasicSnippet` 解析器已删除。
- **保留共享库 `src/SmallBasic.LanguageServices`**（netstandard2.0）：LSP 模型/语义映射/帧读写/内置 server 与文档大纲构建；`SmallBasic.Vsix` 与 `SmallBasic.LanguageServices.Tests` 引用同一程序集。
- **随迁移修复**：LSP server 生命周期不再误绑连接创建 token；`System.Text.Json` 下探到 8.0.5 以覆盖 VS 17.14 随附版本；六个运行/调试命令增加 `EnabledWhen`（仅 `.sb` 活动文档时启用）。
- **测试**：`tests/SmallBasic.LanguageServices.Tests` 直接引用 `SmallBasic.LanguageServices`（不链接编译被测源码），LSP 帧与 JSON-RPC 端到端 23 例全绿；`SmallBasic.Compiler.Tests` 577 例全绿。
- **打包校验**：`build/Package-Vsix.ps1`（原 `Package-Ext-Vsix.ps1`）校验 VSIX v3 条目、`SmallBasic.Vsix.dll`/`SmallBasic.LanguageServices.dll` 与运行载荷、MEF 资产声明、Release 无 PDB、不夹带 Node.js。
- **已验收**：`dotnet build visual_studio_plugin/SmallBasic.VisualStudio.slnx`、两个测试工程、`visual_studio_plugin/build/Package-Vsix.ps1` 全部通过。
- **未落地**：分类着色/折叠/导航栏/调试内联值迁往 Language Configuration + LSP（新框架暂无对应物）；补全/悬停之外的语言特性（签名帮助、重命名、跳转定义）。
