## 组织原则

1. **按功能点编号，不按时间顺序编号**：一个分册只覆盖一组可以独立讨论、实现、验证的语言能力。
2. **顶层总览与分册分离**：公共约束、统一架构、通用门禁留在 [11-SmallBasic语言扩展.md](../11-SmallBasic语言扩展.md)；各语义细节、文件级改动与测试覆盖写在分册。
3. **状态单独标注**：每个分册都明确说明“已实施 / 设计中”，避免把提案与已落地能力混写。
4. **跨分册引用显式化**：某个功能点若依赖另一分册的既有语义，应通过链接说明，不在本页复制整套契约。
