# 01 过程与作用域扩展

> 初始调研与方案日期：2026-10-03
> 实施与验收日期：2026-10-03
> 状态：已实施（Language Extension v1 / v1.1）
> 适用范围：C# / TypeScript 双语言核心，JavaScript / C# / Blazor 三种运行与调试后端，Visual Studio / VS Code / Monaco Playground 三类编辑表面

## 0. 功能范围

本分册覆盖下列能力：

- `Function Name(...) ... EndFunction`
- 带参数的 `Sub Name(...) ... EndSub`
- 过程级 `Dim`
- `Return expression`
- 参数、局部变量与隐式全局的作用域约定
- 无参过程的声明与调用兼容形式

不覆盖：

- `Break` / `Continue`（见 [02-循环控制扩展.md](./02-循环控制扩展.md)）
- `\` / `Mod` / `Math.Div` / `Math.Mod`（见 [03-整除与取余扩展.md](./03-整除与取余扩展.md)）
- `GoSub` / `On Error`（见 [04-GoSub与OnError错误处理.md](./04-GoSub与OnError错误处理.md)）

## 1. 语言契约

### 1.1 语法

```smallbasic
Sub PrintTwice(Value)
  TextWindow.WriteLine(Value)
  TextWindow.WriteLine(Value)
EndSub

Function Add(Left, Right)
  Dim Result
  Result = Left + Right
  Return Result
EndFunction
```

支持的声明与调用形式：

| 类别 | 合法写法 | 说明 |
|---|---|---|
| Sub 声明 | `Sub F`、`Sub F()`、`Sub F(A, B)` | 可省略空括号 |
| Function 声明 | `Function F`、`Function F()`、`Function F(A, B)` | 无参函数同样允许省略空括号 |
| 无参 Sub 调用 | `F`、`F()` | 两种形式等价 |
| 无参 Function 调用 | `Answer = F`、`Answer = F()` | 仅在**值上下文**中允许省括号 |
| 有参过程调用 | `F(1, 2)` | 参数个数必须精确匹配 |

### 1.2 作用域与名称解析

统一契约如下：

1. **未声明变量仍是全局变量**，保留传统 Small Basic 行为。
2. 只有两类名字进入过程局部作用域：
   - 过程参数
   - `Sub` / `Function` 体顶层 `Dim` 声明的变量
3. `Dim` 只允许出现在过程体顶层，不能写在 `If` / `For` / `While` 的嵌套块里。
4. 同一过程内，参数名与 `Dim` 局部名都不允许重复；函数名/子程序名也不能与库名冲突。
5. 过程调用创建独立帧，因此递归、互相调用与事件回调都拥有彼此隔离的参数/locals。

### 1.3 参数、数组与返回

- 实参从左到右求值，按源码顺序绑定到形参。
- 数组值仍是引用语义；把数组作为参数传入时，修改其成员对调用方可见，但把参数名重新赋成别的值只影响当前帧。
- `Return expression` 立即退出当前函数，把结果压回调用方。
- 函数若自然执行到 `EndFunction`，返回空字符串。
- `Return` 出现在 Main 或 `Sub` 中属于诊断错误。

### 1.4 关键诊断

| 场景 | 诊断 |
|---|---|
| `Return` 位于 Main / Sub | `ReturnOutsideFunction` |
| 参数名重复 | `DuplicateParameter` |
| 参数名与局部名重复 | `DuplicateLocalVariable` |
| `Dim` 出现在嵌套控制块中 | `DimMustBeAtProcedureLevel` |
| Function / Sub 实参数量不匹配 | `UnexpectedArgumentsCount` |
| 把 `Function` 绑定给事件 | `FunctionCannotBeEventHandler` |
| 过程名与库名冲突 | `ProcedureConflictsWithLibrary` |
| 在过程内部再次声明过程 | `CannotDefineProcedureInsideProcedure` |

## 2. 编译器与运行时设计

### 2.1 共享模型

两个编译器都采用等价模型：

```text
ProcedureSymbol
  Name
  Kind: Sub | Function
  Parameters[]
  ReturnsValue

ModuleMetadata / RuntimeModule
  Name
  Kind: Program | Sub | Function
  Parameters[]
  Locals[]
  Globals[] (仅 Main)

Frame
  Module
  InstructionIndex
  LocalMemory
  EvaluationStackBase
```

核心原则是：

- **编译期**就决定某个名字是 parameter / local / global；
- **运行期**按已绑定的存储类别访问，不在解释器里猜作用域。

### 2.2 C# 侧改动

主要链路：

- `Scanning/TokenKind.Generated.cs`：新增 `Function` / `EndFunction` / `Dim` / `Return`
- `Parsing/Parser.cs`：解析 Function、参数列表、Return、Dim
- `Binding/Binder.cs`：统一过程表、参数收集、局部声明收集、值上下文与参数数校验
- `Runtime/ModuleEmitter.cs`：发射调用与返回指令
- `SmallBasicEngine.cs`：每次调用创建独立帧；函数返回/自然结束时把值传回调用方

当前已落地的关键点：

1. `ProcedureSymbol` 统一表示 `Sub` / `Function`
2. `Frame.LocalMemory` 存放参数与 `Dim` 局部
3. `ReturnFromFunction()` 负责弹出当前帧并把返回值压回调用方
4. 函数自然走到末尾时自动返回空字符串

### 2.3 TypeScript 侧改动

主要链路：

- `syntax/tokens.ts` / `scanner.ts`
- `syntax/command-parser.ts` / `statements-parser.ts`
- `binding/modules-binder.ts` / `statement-binder.ts` / `expression-binder.ts`
- `emitting/module-emitter.ts`
- `execution-engine.ts`

当前已落地的关键点：

1. TS 两段式 parser 先产生命令，再组装 `FunctionDeclarationSyntax`
2. `ModulesBinder` 统一管理 `ProcedureSymbol`、`ModuleMetadata`
3. `ExecutionEngine.pushProcedure()` 会按模块元数据建本地帧
4. `returnFromFunction()` 与 `completeCurrentFrame()` 分别处理显式返回与自然结束

### 2.4 调用约定

统一调用约定：

1. 调用前先把实参求值压入 evaluation stack
2. 调用指令逆序取参，恢复到原顺序
3. 创建新的 LocalMemory，并写入参数与过程级 `Dim` 初始值
4. 执行结束后恢复 `EvaluationStackBase`
5. Function 额外把返回值压回调用方

这条约定保证：

- `F(G(), H())` 能正确嵌套
- 递归不会污染上一层参数
- 条件断点 / Debug Console 能按 frame 读取 locals

## 3. 调试器影响

### 3.1 快照模型

过程与作用域扩展上线后，调试器不再只暴露单一 `Globals`：

- `stackTrace`：每个调用帧都对应真实 `Sub` / `Function`
- `scopes`：至少区分 `Globals` 与当前 frame 的 `Locals`
- `variables`：参数与 `Dim` 变量按 frame 展开
- `evaluate`：在所选 frame 上下文中求值

已同步覆盖的后端：

- VS Code 内嵌 TS DAP
- `SmallBasic.RunHost` 的 C# DAP
- `SmallBasic.Blazor.RunHost` / 浏览器 WASM 快照模型

### 3.2 调试语义要求

- `stepIn` 进入过程体第一条用户语句
- `stepOut` 在当前帧返回给调用方后暂停
- 条件断点可读取函数参数与局部变量
- 函数自然结束返回空字符串时，不额外暴露“隐藏 return 语句”
