# 06 运行时库与宿主集成

Small Basic 的 20 个标准库对象（Array, Clock, Controls, Desktop, Dictionary, File, Flickr, GraphicsWindow, ImageList, Math, Mouse, Network, Program, Shapes, Sound, Stack, Text, TextWindow, Timer, Turtle）在两个引擎中都是**接口注入**模式：

- .NET：`IEngineLibraries` 聚合 20 个接口（`Libraries.Generated.cs` 生成），宿主提供实现类。
- TS：`RuntimeLibraries` 中各库持有插件接口（如 `ITextWindowLibraryPlugin`），宿主注入实现。

这决定了插件的主要工作量在**宿主 I/O 落地**，而非编译器改造。

> **2026-09-28 现状校准**
>
> - 运行时库在三个宿主机（JS / C# / Blazor）中都是**接口注入**模式，宿主按能力提供实现。
> - 已实现：`TextWindow` 与纯计算库 `Array/Clock/Dictionary/Math/Program/Stack/Text/Timer`；图形库 `GraphicsWindow/Shapes/Turtle` 在 Windows C# 宿主与跨平台 Blazor 后端可用。
> - JS 后端**没有 JS 图形宿主插件**：`GraphicsWindow/Controls/Turtle` 只有元数据与运行时接口层，遇图形程序会显式拒绝。
> - .NET 侧 `SmallBasic.RunHost` 已接入官方 `Microsoft.SmallBasic.Library` 的 `GraphicsWindow`/`Shapes`/`Turtle`，并支持 `--pause` 结尾停留；Blazor 后端在浏览器内以 SVG/Canvas 提供同等图形能力（见 [09](./09-Blazor后端与RunHost.md)）。
> - 尚未实现：`Controls/Desktop/File/Flickr/ImageList/Mouse/Network/Sound`，被调用时抛明确的 `NotSupportedException`。

## 0.1 VSCode 多后端落地（说明）

为兼顾桌面版、VSCode Web、以及 Small Basic 图形程序，运行/调试后端按**能力**拆分。实际实现收敛为三个**显式**后端（由命令或 launch.json 的 `backend` 直接指定），而不是运行时自动路由：

1. **JS 后端（内置，默认）**
  - 形态：扩展内 Pseudoterminal 会话 + 独立 Node CLI 运行宿主（`dist/runhost.js`）。
  - 优点：零外部依赖、最适合 VSCode Web、启动快、与语言服务共享 AST/运行时模型。
  - 职责：`TextWindow`、纯计算库、内嵌 DAP、Web 与其它平台的默认后端。
  - 约束：无图形宿主；遇 `GraphicsWindow/Shapes/Turtle` 显式拒绝。

2. **C#/.NET 后端（Windows 图形）**
  - 形态：独立 `SmallBasic.RunHost`（含内嵌 DAP）。
  - 优点：承载桌面图形宿主、与 Visual Studio 侧复用同一运行时。
  - 职责：Windows 桌面图形程序运行/调试，`Ctrl+F5`/F5 默认。
  - 约束：VSCode Web 不可用；非 Windows 只有便携文本宿主。

3. **Blazor 后端（跨平台图形）**
  - 形态：`SmallBasic.Blazor.RunHost`（Kestrel 宿主）+ 浏览器 WASM 解释器 + SVG/Canvas 渲染。
  - 职责：跨平台图形程序的运行/调试；文本程序留在终端、图形程序才开浏览器。
  - 约束：需要 .NET 8 + ASP.NET Core 8 运行时；VSCode Web 不可用。

4. **能力与共享边界**
  - 三个后端均支持调试；图形能力为 `csharp`(Windows)/`blazor`，文本能力三后端皆有；Web 只支持 `javascript`。
  - 选择规则：Web 强制 `javascript`；桌面 Windows 默认 `csharp`；其它平台默认 `javascript`；图形程序需显式选择 `csharp` 或 `blazor`。
  - 无论后端如何切换，`Compilation`、诊断、补全、悬停、断点吸附规则都保持 IDE 内统一；需要切换的仅是“运行时宿主”和“调试适配器实现”。

## 1. 库实现矩阵（实际状态）

| 库 | 性质 | JS 后端 | C# 便携宿主(net8.0) | C# Windows 宿主(net48/net8.0-windows) | Blazor 后端 |
|---|---|---|---|---|---|
| TextWindow | 控制台 I/O | 集成终端 | 控制台 + `--pause` | 控制台 + `--pause` | 终端（文本程序）/ 页面 |
| Math/Text/Array/Stack/Dictionary/Clock/Program/Timer | 纯计算 | ✅ | ✅ | ✅ | ✅ |
| GraphicsWindow/Shapes/Turtle | 图形 | ❌ 显式拒绝 | ❌ 显式拒绝 | ✅ 官方 `Microsoft.SmallBasic.Library` | ✅ 浏览器 SVG/Canvas |
| Controls/Desktop/File/Flickr/ImageList/Mouse/Network/Sound | 其它 | ❌ `NotSupportedException` | ❌ | ❌ | ❌ |

**探测**：编译期 `RuntimeAnalysis.UsesGraphicsWindow` / `compilation.kind` 已知程序用到哪些库 → 宿主在启动前决定控制台运行还是开图形窗口（Blazor），或直接拒绝（JS/便携 C#）。

## 2. VS Code 侧实现

### 2.1 TextWindow → 集成终端

```ts
// run/text-window-terminal.ts
class TerminalTextWindow implements ITextWindowLibraryPlugin {
  private inputBuffer: BaseValue[] = [];
  constructor(private pty: vscode.Pseudoterminal, private engine: ExecutionEngine) {}
  writeText(value: string, appendNewLine: boolean) { /* pty 写 + 颜色码 */ }
  inputIsNeeded(kind: ValueKind)                   { /* 置等待输入态，回显提示 */ }
  checkInputBuffer(): BaseValue | undefined        { /* 行缓冲弹出；Read/ReadNumber 解锁 */ }
  get/setForegroundColor / get/setBackgroundColor  { /* ANSI 256 色映射 TextWindowColor */ }
}
```

- 颜色：SB 的 16 色枚举 → ANSI escape；`Clear()` → 终端清屏序列。
- `Read()`/`ReadNumber()` 阻塞语义与 DAP 适配器的 `BlockedOnInput` 处理衔接（见 05 §2）。

### 2.2 GraphicsWindow（JS 后端不具备；由 C#/Blazor 承担）

- JS 后端**没有** Webview/Canvas 图形宿主：`GraphicsWindow/Shapes/Turtle` 在 TS 侧只有元数据与运行时接口层，遇图形程序会被命令层显式拒绝并提示切换后端。
- 跨平台图形由 **Blazor 后端**提供（浏览器 WASM 解释器 + SVG/Canvas，见 [09](./09-Blazor后端与RunHost.md)）；Windows 桌面图形由 **C# 宿主**提供。

## 3. VS 侧实现

### 3.1 `SmallBasic.RunHost`（运行/调试宿主）

多目标 `net48;net8.0;net8.0-windows`（`net48`/`net8.0-windows` 定义 `GRAPHICS_HOST` 并使用 WPF），命令形态：

```
SmallBasic.RunHost run --file <program.sb> [--pause]
SmallBasic.RunHost debug            # stdio 原生 DAP
```

`RuntimeLibrariesCollection : IEngineLibraries` 按 `compilation.Analysis.UsesGraphicsWindow` 组装实现：

| 库实现 | 要点 |
|---|---|
| `TextWindowLibrary` | `WriteLine`→`Console.Out`；`Read/ReadNumber`→`Console.ReadLine` + `engine.InputReceived()`；颜色→`Console.ForegroundColor` |
| `ArrayLibrary/ClockLibrary/DictionaryLibrary/MathLibrary/StackLibrary/TextLibrary/TimerLibrary` | 从 vendor 直接引入；`Clock` 用本地时区；`Program.Delay`→`Task.Delay`；`Timer` 触发事件 |
| `GraphicsWindowLibrary/ShapesLibrary/TurtleLibrary` | `GRAPHICS_HOST` 下包裹官方 `Microsoft.SmallBasic.Library`；非图形目标下为 `Unsupported*` |
| `UnsupportedLibraries` | `Controls/Desktop/File/Flickr/ImageList/Mouse/Network/Sound` 抛 `NotSupportedException` |

调试模式见 [05 §4](./05-调试架构设计.md)：`TextWindow` I/O 经 DAP 事件承载，不直接读写控制台。

### 3.2 GraphicsWindow → 官方 WPF 图形库（Windows C# 宿主）

- 图形能力**直接复用官方 NuGet 包 `SmallBasic` 1.2.0 的 `Microsoft.SmallBasic.Library`**（`GraphicsWindow`/`Shapes`/`Turtle`），无需自绘 WPF 宿主。
- `net48` 与 `net8.0-windows` 目标启用 `GRAPHICS_HOST` + `UseWPF`；`net8.0` 便携目标在编译时排除这三个库的实现文件。
- Blazor 后端另有一套浏览器实现（[09](./09-Blazor后端与RunHost.md)）。

## 4. 安全策略（当前状态）

- `File/Flickr/Network/Desktop` 等库**尚未实现**，被调用时抛 `NotSupportedException`；因此原计划的 `smallbasic.file.rootPath`、`smallbasic.enableNetwork` 等设置项**尚不存在**。
- 运行/调试都在独立子进程中进行，可随时由 IDE 终止。
- Blazor 后端 Kestrel 只监听 `127.0.0.1` 随机端口，会话用随机标识（见 [09](./09-Blazor后端与RunHost.md)）。

## 5. 库文档数据流

```
SmallBasicOnline 的本地化文档资源（拷贝于 vendor/SmallBasicOnline/src/strings/documentation*.ts）
   └─ setDocumentationLocale(locale)
        ├─ VS Code: 补全 detail/documentation、hover markdown
        └─ VS:      库元数据 (Libraries.Generated.cs) 的本地化描述 → 补全/QuickInfo
```

- TS 侧文档文案内置于 vendor（源自 HomeSite 的 XML，已在 SmallBasicOnline 中整理），扩展按 VS Code UI 语言选择；取不到时回退英文。
- .NET 侧描述来自 vendor 生成的库元数据与本地化资源（.resx）。
- **原计划的构建期 `library-docs.json` 生成器与双引擎元数据对账尚未落地。**

## 6. 现状小结

- `TextWindow.WriteLine/Write/Read/ReadNumber/Clear` + 颜色 + 8 个纯计算库在三后端均可用。
- 图形库在 Windows C# 宿主与 Blazor 后端可用；JS 与便携 C# 宿主显式拒绝图形程序。
- 所有宿主 I/O 实现可注入假实现（沿用 `TextWindowTestBuffer` 模式），保证库逻辑可脱离 IDE 单测。
